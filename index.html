Boat One

Fundamentals

1Statistics & Machine Learning (before any code)

If you can't explain why a model overfits, no library will save you. Build intuition, not formula memory.

Statistics

  • Distributions, probability, Bayes' theorem
  • Sampling, confidence intervals, hypothesis testing
  • A/B testing and statistical significance
  • Correlation vs. causation, and why it matters in real decisions

Machine Learning

  • Regression, classification, tree-based models, clustering
  • Bias–variance, regularization, cross-validation
  • Choosing the right metric: precision vs. recall depends on the cost of being wrong

Start with

  • StatQuestintuition on stats and ML
  • Google ML Crash Coursea hands-on intro

2SQL first, then Python

At every company, your data sits in a warehouse (Snowflake, BigQuery, Redshift, Postgres). SQL is how you get it out. Python is how you do everything after. Nobody hands you a clean CSV.

SQL

  • Joins, subqueries, CTEs
  • Aggregations and window functions
  • Date and time logic

Python

  • pandas: work with tables (load, filter, group, join, clean)
  • NumPy: the math underneath (arrays, matrices, fast numerics)
  • scikit-learn: build ML models (train, preprocess, evaluate)
  • Matplotlib / Seaborn: see the data (plots, distributions, charts)

Practice

  • HackerRank Data Scientist trackscenario-based SQL and Python problems that mirror how data scientists actually get tested

Write code daily. When you get stuck, ask an LLM to explain the error, but you write the fix.

3Exploratory Data Analysis & Feature Engineering

Real data is never clean. Most of the job happens before you train anything.

EDA

  • Profile before you model: types, distributions, missing values, duplicates, outliers
  • Find patterns and data-quality issues
  • Visualize and communicate what you found

Feature Engineering

  • Encode categoricals, scale numerics when appropriate
  • Build features from dates, text, and behavior
  • Handle imbalanced data
  • Catch data leakage (the silent project-killer)
  • Build preprocessing as a pipeline, not a pile of notebook cells

Data (real only)

  • Kaggle Datasets
  • UCI Machine Learning Repository
  • Google Dataset Search

4Product Sense & Business Knowledge

You can be great at ML, but if you can't turn a business problem into the right metric, the model doesn't matter.

  • Turn a vague ask ("why is churn up?") into a measurable question
  • Define success before you build; pick the KPI
  • Understand funnels, retention, user behavior
  • Design and interpret experiments
  • Make the recommendation, and explain it to someone who will never read your code

Boat Two

Where the field is going

5LLM Evals

LLMs don't have one right answer, so proving your system is actually good is becoming the job.

  • Traditional ML evaluation vs. LLM evaluation
  • Eval datasets and test cases
  • Human evaluation and LLM-as-a-judge
  • Hallucination, groundedness, factual correctness
  • RAG evaluation and retrieval quality
  • Regression testing and monitoring

Guide

  • LangSmith: Evaluation Types

6Build with Coding Agents & Understand Harnesses

This is the step most roadmaps skip.

  • Take the ML projects you already built. Feed the same data and the same preprocessing into Claude Code or Codex, and make them better: faster pipeline, cleaner features, stronger evaluation.
  • Learn what a harness is: the tools, memory, and loop around the model
  • Learn context engineering: why the same model gives great output in one setup and garbage in another
  • Rule: if you can't explain the code the agent wrote, you don't own it yet

Same problems, AI on your side. That's how engineering is done now.

7Projects: work backwards

Your resume needs three projects, one in each domain: healthcare, finance, retail. Don't invent a problem. Find one that industry is already facing and build the solution.

  1. Pull 10–20 job descriptions for the role you want
  2. Tally the skills that keep repeating
  3. Make sure your three projects prove exactly those skills

A strong project has

  • A real problem and real data
  • EDA and thoughtful feature engineering
  • A baseline before anything fancy
  • The right metric, and honest limitations
  • A README a recruiter understands in 60 seconds
  • Bonus: deployed as a simple app or API

My favorite version: pick a research paper, recreate it from scratch, let it break, and debug it until you understand why. That write-up is your interview story.

8Interviews

  • Fundamentals: stats, ML, experiments, evaluation
  • Coding: SQL + Python, explaining your thinking out loud
  • Product & AI sense: metrics, trade-offs, "how would you evaluate this AI feature?"

Apply before you feel ready. You never will.
